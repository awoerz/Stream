## Summary
Reduce the prominence of the refresh board button and move it to a less intrusive location in the UI while keeping it accessible for manual use.

## Why
With file watchers automatically updating the Kanban board, the refresh button is no longer a primary action. Keeping it highly visible adds unnecessary UI clutter. Relocating it improves user experience while still supporting edge cases or impatient users.

## Acceptance Criteria
- Refresh button is no longer in the primary action area
- Button is moved to a secondary or less prominent location (e.g., toolbar, overflow menu, or small icon)
- Button remains functional and triggers a full board refresh when clicked
- UI layout is cleaner and more focused on core actions (task creation, editing, etc.)
- No regression in board refresh behavior

## Context
Stream previously required manual refreshes to sync the Kanban board with the file system. With file watchers now handling updates automatically, the refresh button is largely redundant but still useful as a fallback.

## Notes
- Consider placing the button in a settings menu or as a small icon in the header
- Optionally add a tooltip indicating it is rarely needed
- Ensure accessibility (keyboard navigation, hover state)
- Avoid removing entirely to preserve a manual override
