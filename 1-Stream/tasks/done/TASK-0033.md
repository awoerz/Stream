## Summary
Allow users to edit task details directly from the UI when the task is located in the backlog folder.

## Why
Currently, tasks must be edited manually in markdown files, which breaks flow and increases friction. Enabling UI-based editing improves usability and makes backlog grooming faster and more intuitive.

## Acceptance Criteria
- User can open a backlog task from the UI
- User can modify task fields (title, summary, acceptance criteria, notes, etc.)
- Changes are saved back to the corresponding markdown file
- UI reflects updated task data immediately after save
- Editing is restricted to tasks in the backlog folder only
- No data loss or corruption occurs during save operations

## Context
Stream uses markdown files as the source of truth for tasks. The backlog folder represents tasks that are not yet in progress, making it the safest place to allow editing without interfering with active workflow.

## Notes
- Parse markdown into editable fields and serialize back on save
- Consider using a modal or side panel for editing
- Validate markdown structure before saving
- Handle concurrent file changes safely (watcher integration)
- Future enhancement: extend editing to other statuses with proper safeguards
